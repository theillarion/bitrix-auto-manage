# Changelog

Все заметные изменения проекта документируются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [семантическое (SemVer)](https://semver.org/lang/ru/).

## Как версионируется проект

- Все изменения фиксируются в секции `[Unreleased]` по ходу коммитов. Секция
  превращается в релиз `[X.Y.Z] - дата` только по явной команде владельца;
  одновременно с этим обновляются версия в `pyproject.toml` и `__init__.py`
  и ставится git-тег `vX.Y.Z`.
- Версия задается в `pyproject.toml` (`[project] version`) и дублируется в
  `src/bitrix_auto_manage/__init__.py` (`__version__`).
- Пока проект младше 1.0: минорная версия (`0.x`) может нести и новые
  функции, и несовместимые изменения формата YAML или CLI; патч — только
  исправления без изменения поведения.
- С 1.0: минорная — обратно совместимые функции, патч — исправления,
  мажорная — несовместимые изменения.

## [0.5.0] - 2026-10-24

### Добавлено

- YAML: `schedule.apply_time` поддерживает окно случайного времени
  `"HH:MM-HH:MM"` — строго в пределах одного дня (`start < end`; перевёрнутый
  `15:00-13:00`, ночной `22:00-02:00` и вырожденный `16:00-16:00` — ошибки
  конфигурации с понятным сообщением). После каждого успешного прогона демон
  выбирает случайную минуту (границы включительно) из полного окна ближайшего
  дня, окно которого ещё не началось: если прогон завершился раньше начала
  окна — окно сегодня, иначе завтра. Выбранный момент всегда строго в
  будущем, пауза меньше 48 часов, второго планового прогона в тот же день
  не бывает. Прежний формат точного времени `"HH:MM"` работает
  как вырожденное окно без рандома (миграция конфига не требуется). Незакавыченное
  `apply_time: 16:00` (YAML читает его как число 960) теперь даёт ошибку
  с подсказкой про кавычки; лог следующего запуска показывает окно:
  `Next run at 17:23 (in 01:45, window 16:00-19:00).`

- CI: публикация Docker-образа в GHCR по тегу `vX.Y.Z` — workflow
  `.github/workflows/docker.yml` (multi-arch linux/amd64+arm64, теги
  `X.Y.Z`/`X.Y`/`latest`); установка из реестра без клона и сборки —
  `docker-compose.ghcr.yml`, `install.sh` (POSIX sh — однострочная установка
  в стиле oh-my-zsh: `sh -c "$(curl ...)"`; с fail-fast проверкой Docker
  и Compose v2 перед установкой), раздел README 2.1.1,
  `.dockerignore`.

### Изменено

- Дефолт `schedule.apply_time` — окно `16:00-19:00` вместо точного `18:05`
  (обновлены `config/schedule.example.yaml` и зеркалящий пример в README).
- Справка CLI `bitrix-auto daemon`: «прогон окна каждый день в случайное
  время внутри schedule.apply_time».

## [0.4.1] - 2026-10-23

### Добавлено

  GitHub Release при пуше тега `vX.Y.Z` или вручную через
  `workflow_dispatch` с входом `tag`: заголовок «Version X.Y.Z», ноты —

### Изменено

- Демон: лог после успешного прогона теперь показывает время следующего
  запуска по таймзоне конфига и длительность паузы — `Next run at 18:45
  (in 18:34).` вместо `Next run in 18:34.` (длительность выглядела как
  время); лог ветки повтора после ошибки не изменился (`Retrying in N
  minutes.`).
- README: примеры `preview` в быстром старте (Docker и локальный) без
  привязки к дате — флаг `--date 2026-10-19 --days 1` заменён на
  `--days 3` (план на ближайшие три дня от сегодня).

## [0.3.0] - 2026-10-22

### Удалено

- `kind: workday` больше не поддерживается — рабочий день создаётся
  автоматически (проход СКУД или робот удалённого дня). Конфигурации
  с `kind: workday` теперь отклоняются валидацией (ошибка конфигурации),
  а не молча работают; удалён соответствующий код диспетчеризации и
  ветки `workday` в порядке применения задач.

### Добавлено

- YAML: ключ `schedule.skip_dates` — список дат `YYYY-MM-DD`, полностью
  исключаемых из планирования: за них не создаётся ни удалёнка, ни записи
  учета (действует в `daemon`, `apply` и `preview`, включая явные окна
  `--date`/`--days`; в журнале прогона такие даты отмечаются строкой
  `<дата>: skipped by skip_dates`). При слиянии нескольких файлов список
  позднего файла заменяет ранний.
- Демон перечитывает YAML-конфиг перед каждым прогоном (включая первый):
  правки подхватываются без рестарта контейнера. Ошибка загрузки при
  перечитывании — неудачный прогон: лог причины и повтор через
  `retry_minutes`, ранее загруженный конфиг повторно не применяется; битый
  конфиг на первом старте завершает демон с кодом 1. Нечитаемый файл YAML
  теперь даёт ошибку конфигурации, а не traceback.
- CI: workflow GitHub Actions `.github/workflows/tests.yml` (push и
  pull request; матрица Python 3.11–3.14) — клонирует публичный SDK
  `sdk-bitrix-time-manager` в соседний каталог, ставит его и пакет
  editable с dev-инструментами, затем `pytest` с покрытием, `ruff check`
  и `mypy src`.
- README: шапка для GitHub в стиле SDK-репозитория — центрированный блок
  с теглайном и построчными бейджами shields.io; итоговый набор бейджей:
  release (версия релиза со ссылкой на тег), Python >=3.11, лицензия MIT,
  stars и tests (badge.svg workflow `tests.yml`); бейджей `code style: ruff`
  и `typing: mypy strict` в итоговом наборе нет. Прежняя преамбула «О проекте»
  влита в теглайн и раздел «Возможности», ссылка на SDK заменена на публичный
  адрес репозитория.
- Лицензия MIT: текст в `LICENSE` (тот же правообладатель, что у SDK
  `bitrix-time-manager`), объявление в `pyproject.toml` (`license = "MIT"`,
  `license-files`).
- Документация: `docs/commands.md` — полный справочник CLI `bitrix-auto`
  (все команды и флаги с дефолтами, семантика окна `--date`/`--days` тремя
  комбинациями, коды выхода, примеры локально и в Docker); ссылки на него
  из README и docs/setup.md.

### Изменено

- README: уточнено описание SDK в шапке — SDK даёт Python API и CLI
  `bitrix-time`, а не «REST-клиент»; в быстрый старт Docker добавлены шаги
  проверки перед запуском демона (`check` и `preview` через
  `docker compose run --rm bitrix-auto`) и примечание о выполнении
  CLI-команд в контейнере.
- README: нумерованная структура разделов с подсекциями (быстрый старт
  разделен на Docker и локальный запуск) и вложенное оглавление «Содержание»
  с якорями GitHub; раздел «Возможности» перенесен под оглавление, ссылки
  на CHANGELOG.md и docs/setup.md вынесены в раздел «Документация».
- README: быстрые старты (Docker и локальный) разбиты на этапы: подготовка
  окружения, предварительная проверка, запуск, проверка логов; в локальный
  старт добавлены подготовка `config/schedule.yaml` (копирование example
  и редактирование) и предварительная read-only проверка `bitrix-auto check`.

## [0.2.0] - 2026-10-21

### Добавлено

- Тесты `runner` (прогон окна дат, обработка ошибок SDK, `show_day`), `scheduler`
  (расчёт следующего запуска, коды выхода `--once`, пауза до `apply_time` и пауза
  повтора) и CLI (`check`, `preview`, `apply`, `show`, `daemon`, запуск
  `python -m bitrix_auto_manage`) — на фейках SDK, без сети и реального портала;
  строковое покрытие всех модулей пакета доведено со 60% до 100%.

### Безопасность

- `.gitignore`: добавлен каталог `.state/` (дефолтный путь SQLite-журнала
  host/cron-режима — `.state/operations.sqlite3` относительно каталога
  запуска) — устранена публикация журнала с персональными данными при
  `git add -A`; каталог также внесен в Never-список `AGENTS.md`. README
  и `.env.example` теперь честно документируют хост-дефолт журнала
  и рекомендуют задавать `BITRIX_STATE_PATH` при запуске не из корня репо.

## [0.1.0] - 2026-10-20

Первый пре-релиз: автоматизация Time-менеджера Bitrix24 по YAML-расписанию.

### Добавлено

- CLI `bitrix-auto`: команды `check`, `preview`, `apply`, `show`, `daemon`
  (и `daemon --once` для cron / Планировщика Windows); общие флаги `--config`
  (файл или каталог, можно повторять), `--env-file`, `-v`, `--version`.
- YAML-конфигурация: `timezone`, секция `schedule` (`apply_time`,
  `horizon_days`, `backfill_days`, `retry_minutes`) и список `tasks` с видами
  `remote` и `time_entry`; дни недели на русском и английском, диапазоны через
  дефис; строгая валидация — неизвестные поля запрещены.
- Несколько YAML-файлов в каталоге `config/` объединяются по алфавиту:
  скалярные значения перезаписываются, списки `tasks` дополняются; файлы
  с `.example.` в имени игнорируются.
- Политика `on_existing_entries` для учета времени: `skip` (по умолчанию) не
  добавляет запись, если за дату уже есть любая; `append` — добавляет поверх
  (портал суммирует записи за день).
- Идемпотентность через SDK: стабильные ключи `auto:<дата>:<хэш>`, статусы
  `created`/`existing`, SQLite-журнал операций против дублей при повторных
  прогонах и потерянных ответах сети.
- Docker: Dockerfile (python:3.12-slim) и docker-compose с монтированием
  `config/` (только чтение) и `state/`; подключение соседнего SDK через
  переменную `BITRIX_SDK_PATH`.
- Документация: README с преамбулой и оглавлением; `docs/setup.md` —
  пошаговое создание входящего вебхука Bitrix24 и полный справочник по файлу
  расписания.
- Разработка: 25 offline-тестов (pytest), ruff, mypy strict.
